## 一、环境前提

### 1.1 所需软件

| 软件 | 最低版本 | 说明 |
|------|---------|------|
| **Docker Desktop** | 4.x+ | Windows/macOS 需安装 Docker Desktop 并启动 |
| **Node.js** | 18+ | 项目后端运行环境 |
| **npm** | 9+ | 随 Node.js 安装 |

### 1.2 检查 Docker 是否就绪

```bash
docker --version
# 输出示例: Docker version 29.6.2, build dfc4efb

docker ps
# 能正常输出容器列表（即使为空）说明 Docker 守护进程已运行
```

> **如果 `docker ps` 报错**：说明 Docker Desktop 没启动。打开 Docker Desktop 应用，等待右下角状态变为 "Running" 后重试。

### 1.3 为什么选择 pgvector 镜像？

本项目使用智谱 AI 的 `embedding-3` 模型生成 **1536 维**向量，存储和检索需要 PostgreSQL 的 `vector` 类型支持。`pgvector/pgvector:pg16` 镜像基于 PostgreSQL 16，**预装了 pgvector 扩展**，无需手动编译。

如果使用普通 `postgres` 镜像，需要额外编译安装 pgvector，步骤繁琐且容易出错。

## 二、理解项目数据库配置

在搭建数据库之前，先搞清楚项目需要什么。

### 2.1 查看 .env 配置

项目数据库连接信息在 `server/.env` 文件中：

```bash
# 文件路径: server/.env

# ─── PostgreSQL ───────────────────────────
PG_HOST=localhost
PG_PORT=5432
PG_USER=postgres
PG_PASSWORD=123456
PG_DATABASE=jisu_ai
```

这些值会在 `server/src/db/postgres.js` 中被读取：

```javascript
// server/src/db/postgres.js
import pg from 'pg';
import 'dotenv/config';

const { Pool } = pg;

export const pool = new Pool({
  host:     process.env.PG_HOST     || 'localhost',
  port:     parseInt(process.env.PG_PORT || '5432'),
  user:     process.env.PG_USER     || 'postgres',
  password: process.env.PG_PASSWORD || 'postgres',
  database: process.env.PG_DATABASE || 'langchain_course',
});
```

> **注意**：代码中的 fallback 默认值是 `langchain_course`，但 `.env` 覆盖为 `jisu_ai`。以 `.env` 为准。

### 2.2 数据库需求清单

| 需求 | 说明 |
|------|------|
| 数据库 `jisu_ai` | Docker 容器启动时自动创建 |
| `vector` 扩展 | `cache_entries.embedding` 字段使用 `vector(1536)` 类型 |
| `pgcrypto` 扩展 | `conversations.id` 默认值使用 `gen_random_uuid()` |
| 6 张业务表 | 通过迁移脚本创建（见第六步） |
| 1 张 RAG 向量表 | `knowledge_embeddings`，通过 `npm run ingest` 创建 |

## 三、启动 Docker 容器

有两种方式，效果完全一样。

### 方式一：使用 docker-compose.yml（推荐）

项目根目录已有 `docker-compose.yml` 文件：

```yaml
# docker-compose.yml
services:
  postgres:
    image: pgvector/pgvector:pg16
    container_name: pgvector-jisu
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: 123456
      POSTGRES_DB: jisu_ai
    ports:
      - "5432:5432"
    volumes:
      - jisu_pgdata:/var/lib/postgresql/data
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d jisu_ai"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  jisu_pgdata:
```

启动命令：

```bash
cd C:/Users/s1523/Downloads/jisu-ai-customer
docker compose up -d
```

**各参数含义**：

| 参数 | 值 | 作用 |
|------|-----|------|
| `image` | `pgvector/pgvector:pg16` | PostgreSQL 16 + 预装 pgvector |
| `container_name` | `pgvector-jisu` | 容器名称，方便后续 `docker exec` 引用 |
| `POSTGRES_USER` | `postgres` | 超级用户名 |
| `POSTGRES_PASSWORD` | `123456` | 密码（与 `.env` 一致） |
| `POSTGRES_DB` | `jisu_ai` | 容器启动时**自动创建**的数据库 |
| `ports` | `5432:5432` | 宿主机 5432 → 容器 5432 |
| `volumes` | `jisu_pgdata` | 数据持久化卷，容器删除后数据不丢失 |

### 方式二：直接 docker run

如果你不想用 docker-compose，也可以直接命令行启动：

```bash
docker run -d \
  --name pgvector-jisu \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=123456 \
  -e POSTGRES_DB=jisu_ai \
  -p 5432:5432 \
  -v jisu_pgdata:/var/lib/postgresql/data \
  --restart unless-stopped \
  pgvector/pgvector:pg16
```

### 预期输出

```
[+] Running 2/2
 ✔ Volume "jisu-ai-customer_jisu_pgdata"  Created
 ✔ Container pgvector-jisu                 Started
```

> Docker 会先拉取 `pgvector/pgvector:pg16` 镜像（约 400MB），首次拉取需要 1-2 分钟。
>
> **关键点**：`POSTGRES_DB=jisu_ai` 环境变量让 Docker 在容器首次启动时自动创建 `jisu_ai` 数据库，**不需要手动执行 `CREATE DATABASE`**。

## 五、启用 PostgreSQL 扩展

Docker 容器虽然预装了 pgvector，但**扩展需要在使用它的数据库中手动启用**。

### 5.1 启用扩展

```bash
docker exec pgvector-jisu psql -U postgres -d jisu_ai \
  -c "CREATE EXTENSION IF NOT EXISTS vector;" \
  -c "CREATE EXTENSION IF NOT EXISTS pgcrypto;"
```

预期输出：

```
CREATE EXTENSION
CREATE EXTENSION
```

### 5.2 验证扩展状态

```bash
docker exec pgvector-jisu psql -U postgres -d jisu_ai -c "\dx"
```

预期输出：

```
                              List of installed extensions
   Name   | Version |   Schema   |                     Description
----------+---------+------------+------------------------------------------------------
 pgcrypto | 1.3     | public     | cryptographic functions
 plpgsql  | 1.0     | pg_catalog | PL/pgSQL procedural language
 vector   | 0.8.5   | public     | vector data type and ivfflat and hnsw access methods
(3 rows)
```

### 5.3 两个扩展分别干什么？

| 扩展 | 版本 | 提供的能力 | 被哪张表使用 |
|------|------|----------|------------|
| `vector` | 0.8.5 | `vector(1536)` 数据类型 + 向量相似度搜索（余弦距离、L2 距离） | `cache_entries.embedding` |
| `pgcrypto` | 1.3 | `gen_random_uuid()` 函数，生成 UUID 作为主键 | `conversations.id` |
| `plpgsql` | 1.0 | PostgreSQL 默认过程语言（系统自带，无需关心） | — |

> **为什么不提前启用？** PostgreSQL 的扩展是**数据库级别**的，不是实例级别的。如果新建了另一个数据库，需要再次执行 `CREATE EXTENSION`。

## 六、创建数据库迁移脚本

### 6.1 创建迁移目录

```bash
mkdir -p server/src/db/migrations
```

### 6.2 创建 6 个 SQL 文件

每个文件对应一张表，文件名前缀数字代表执行顺序（`001` 必须在 `002` 之前执行，因为 `messages` 表有外键引用 `conversations`）。

#### 文件 1：`server/src/db/migrations/001_conversations.sql`

会话管理表。每次用户打开新对话时创建一条记录。

```sql
-- 001_conversations.sql
-- 会话管理表 (F01 会话记忆持久化)
-- 依赖: pgcrypto 扩展 (gen_random_uuid)

CREATE TABLE IF NOT EXISTS conversations (
  id          VARCHAR(64) PRIMARY KEY DEFAULT gen_random_uuid()::text,
  session_id  VARCHAR(64) UNIQUE NOT NULL,
  title       VARCHAR(200) NOT NULL DEFAULT '新对话',
  user_id     VARCHAR(64) DEFAULT 'anonymous',
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_conversations_session ON conversations(session_id);
CREATE INDEX IF NOT EXISTS idx_conversations_user    ON conversations(user_id);
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | VARCHAR(64) PK | 自动生成 UUID（依赖 pgcrypto） |
| `session_id` | VARCHAR(64) UNIQUE | 前端生成的会话唯一标识 |
| `title` | VARCHAR(200) | 会话标题，默认"新对话" |
| `user_id` | VARCHAR(64) | 用户标识，默认"anonymous" |
| `created_at` | TIMESTAMPTZ | 创建时间，自动填充 |

#### 文件 2：`server/src/db/migrations/002_messages.sql`

消息持久化表。存储每条用户/AI 消息。

```sql
-- 002_messages.sql
-- 消息持久化表 (F01 会话记忆持久化)
-- 外键依赖: conversations.session_id (必须先执行 001)

CREATE TABLE IF NOT EXISTS messages (
  id          SERIAL PRIMARY KEY,
  session_id  VARCHAR(64) NOT NULL REFERENCES conversations(session_id) ON DELETE CASCADE,
  role        VARCHAR(20) NOT NULL CHECK (role IN ('user', 'assistant', 'system')),
  content     TEXT NOT NULL,
  metadata    JSONB DEFAULT '{}',
  token_count INT DEFAULT 0,
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_messages_session ON messages(session_id);
CREATE INDEX IF NOT EXISTS idx_messages_created ON messages(session_id, created_at);
```

**关键字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `session_id` | VARCHAR(64) FK | 外键关联 conversations，删除会话时级联删除消息（`ON DELETE CASCADE`） |
| `role` | VARCHAR(20) | CHECK 约束：只能是 `user` / `assistant` / `system` |
| `content` | TEXT | 消息正文 |
| `metadata` | JSONB | 扩展元数据（如 mode、cached、time 等） |
| `token_count` | INT | 消息的 token 数量，用于成本统计 |

#### 文件 3：`server/src/db/migrations/003_guardrail_logs.sql`

安全护栏日志表。记录被安全规则拦截的用户输入。

```sql
-- 003_guardrail_logs.sql
-- 安全护栏拦截日志表 (F07 安全护栏)

CREATE TABLE IF NOT EXISTS guardrail_logs (
  id            SERIAL PRIMARY KEY,
  session_id    VARCHAR(64),
  input_text    TEXT NOT NULL,
  block_reason  VARCHAR(100),
  created_at    TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_guardrail_session ON guardrail_logs(session_id);
```

#### 文件 4：`server/src/db/migrations/004_cost_records.sql`

模型调用成本追踪表。每次调用 LLM 时记录 token 消耗和费用。

```sql
-- 004_cost_records.sql
-- 模型调用成本追踪表 (F09 成本追踪与可观测性)

CREATE TABLE IF NOT EXISTS cost_records (
  id            SERIAL PRIMARY KEY,
  session_id    VARCHAR(64),
  node          VARCHAR(50) NOT NULL,
  model         VARCHAR(100) NOT NULL,
  input_tokens  INT DEFAULT 0,
  output_tokens INT DEFAULT 0,
  cost          DECIMAL(10,6) DEFAULT 0,
  created_at    TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_cost_session ON cost_records(session_id);
CREATE INDEX IF NOT EXISTS idx_cost_model  ON cost_records(model);
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `node` | VARCHAR(50) | 调用来源节点（如 `intentRouter`、`ragNode`、`orderAgent`） |
| `model` | VARCHAR(100) | 模型名称（如 `deepseek-chat`、`embedding-3`） |
| `input_tokens` | INT | 输入 token 数 |
| `output_tokens` | INT | 输出 token 数 |
| `cost` | DECIMAL(10,6) | 本次调用费用（精度到小数点后 6 位） |

#### 文件 5：`server/src/db/migrations/005_cache_entries.sql`

语义缓存表。通过向量相似度匹配历史问答，避免重复调用 LLM。

```sql
-- 005_cache_entries.sql
-- 语义缓存表 (F06 语义缓存)
-- 依赖: vector 扩展 (vector 类型)

CREATE TABLE IF NOT EXISTS cache_entries (
  id          SERIAL PRIMARY KEY,
  question    TEXT NOT NULL,
  answer      TEXT NOT NULL,
  embedding   vector(1536),  -- 智谱 AI embedding-3 维度，与 embedding.js 一致
  hit_count   INT DEFAULT 0,
  expires_at  TIMESTAMPTZ DEFAULT NOW() + INTERVAL '24 hours',
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_cache_expires ON cache_entries(expires_at);
```

> **为什么是 1536 维？** 项目使用智谱 AI 的 `embedding-3` 模型（见 `server/src/models/embedding.js`），该模型输出 1536 维向量。`vector(1536)` 必须与 embedding 模型维度完全一致，否则写入时会报错。

#### 文件 6：`server/src/db/migrations/006_kb_documents.sql`

知识库文档管理表。记录上传的文档及其处理状态。

```sql
-- 006_kb_documents.sql
-- 知识库文档管理表 (F02 知识库管理)

CREATE TABLE IF NOT EXISTS kb_documents (
  id           SERIAL PRIMARY KEY,
  filename     VARCHAR(255) NOT NULL,
  file_type    VARCHAR(20) NOT NULL,
  chunk_count  INT DEFAULT 0,
  status       VARCHAR(20) DEFAULT 'processing',
  uploaded_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_kbdocs_status ON kb_documents(status);
```

**status 字段状态流转**：`processing` → `ready` / `failed`

### 6.3 迁移文件依赖关系

```
001_conversations  ←── 无依赖（第一个执行）
       ↑
002_messages        ←── 外键引用 conversations.session_id
003_guardrail_logs  ←── 无依赖
004_cost_records    ←── 无依赖
005_cache_entries   ←── 依赖 vector 扩展（第五步已启用）
006_kb_documents    ←── 无依赖
```

> **执行顺序**：`001` 必须最先执行，`002` 必须在 `001` 之后。`003`~`006` 之间无顺序要求，但建议按编号顺序执行。

## 九、知识库入库（RAG 向量表）

以上 6 张表是业务扩展表。项目还有一张 RAG 向量表 `knowledge_embeddings`，由 `ingest.js` 脚本自动创建和填充。

### 9.1 入库脚本做了什么

```javascript
// server/src/scripts/ingest.js（关键逻辑）

// 1. 读取知识库文件
const docs = loadDocs();  // 读取 products.md + policies.md

// 2. 切分文档
const chunks = await splitter.splitDocuments(docs);  // chunkSize=500, overlap=50

// 3. 自动建表（如果不存在）
await client.query(`
  CREATE TABLE IF NOT EXISTS knowledge_embeddings (
    id       bigserial PRIMARY KEY,
    content  text,
    metadata jsonb,
    embedding vector(1536)
  );
`);

// 4. 清空旧数据
await client.query("TRUNCATE knowledge_embeddings;");

// 5. 调用智谱 AI 生成向量并写入
await PGVectorStore.fromDocuments(chunks, embeddings, PG_CONFIG);
```

## 十四、常见问题排查

### Q1: `docker compose up -d` 报端口被占用

```
Error: Bind for 0.0.0.0:5432 failed: port is already allocated
```

**原因**：宿主机 5432 端口已被其他程序（可能是本地安装的 PostgreSQL）占用。

**解决方案**（二选一）：

```bash
# 方案 A：停掉本地 PostgreSQL 服务
# Windows:  服务管理器 → 找到 postgresql-x64-16 → 停止
# macOS:    brew services stop postgresql

# 方案 B：修改 docker-compose.yml 中的端口映射
ports:
  - "5433:5432"   # 宿主机用 5433，容器内仍是 5432
# 同时修改 server/.env: PG_PORT=5433
```

### Q2: `CREATE EXTENSION vector` 报错

```
ERROR: could not open extension control file "/usr/share/postgresql/16/extension/vector.control"
```

**原因**：使用的不是 pgvector 镜像，而是普通的 postgres 镜像。

**解决方案**：确认镜像名称是 `pgvector/pgvector:pg16`，不是 `postgres:16`。

```bash
docker compose down -v
# 修改 docker-compose.yml 中的 image 为 pgvector/pgvector:pg16
docker compose up -d
```

### Q3: 执行迁移脚本报外键错误

```
ERROR: relation "conversations" does not exist
```

**原因**：`002_messages.sql` 在 `001_conversations.sql` 之前执行了。

**解决方案**：严格按 001→006 顺序执行。`messages` 表的外键 `REFERENCES conversations(session_id)` 要求 `conversations` 表必须先存在。

### Q4: `npm run ingest` 报错 `ZHIPU_API_KEY` 无效

```
Error: 401 Authentication Error
```

**原因**：智谱 AI API Key 过期或余额不足。

**解决方案**：
1. 登录 [智谱 AI 开放平台](https://open.bigmodel.cn)
2. 检查 API Key 是否有效
3. 检查账户余额
4. 更新 `server/.env` 中的 `ZHIPU_API_KEY`

### Q5: Node.js 连接数据库报错

```
Error: connect ECONNREFUSED 127.0.0.1:5432
```

**原因**：Docker 容器未运行，或端口映射不正确。

**解决方案**：

```bash
# 检查容器是否在运行
docker ps | grep pgvector-jisu

# 如果没有，启动它
docker compose up -d

# 等待几秒后重试
```

### Q6: 重复执行迁移脚本会出错吗？

**不会**。所有 `CREATE TABLE` 和 `CREATE INDEX` 语句都使用了 `IF NOT EXISTS`，重复执行只会输出 `NOTICE: relation already exists, skipping`，不会报错。

### Q7: 如何完全重置数据库？

```bash
# 停止容器并删除数据卷
docker compose down -v

# 重新启动（会自动创建新的空数据库）
docker compose up -d

# 等待几秒后重新执行迁移
bash init-database.sh
```
